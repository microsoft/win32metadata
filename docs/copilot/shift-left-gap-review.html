Official Rust baseline

Rust consumers use the committed crates/libs/default/Windows.Win32.winmd. It is generated from the committed metadata/win32 and metadata/wdk RDL snapshots.

Review question: Should the final contract be raw-header fidelity in the winmd, with CsWin32 honoring use-site projection attributes, or should selected metadata types themselves retain today's opinionated aliases? The examples call out where that choice matters.
Scope rule for this revision: every API example below exists in upstream windows-rs's committed RDL and canonical Windows.Win32.winmd.
Cross-cutting metadata contract

Meta attributes: inferred facts versus explicit header contracts

Some metadata does not change the ABI declaration but is still part of the contract consumed by projections. Mechanical inference is useful, but every inferred fact should also have an explicit, ABI-neutral header annotation for exceptions and long-term ownership.

Metadatawindows-rs todayProposed header vocabularyDecision
DllImport, entry point, calling convention Function-to-DLL mapping is inferred from SDK COFF import libraries; aliases and calling convention come from the declaration. _Win32_ImportLibrary_("name.dll"); keep explicit entry-point/name vocabulary for exceptions. Keep import-library scanning as the default, but preserve the resulting ImplMap/DllImport in metadata.
SetLastError Not safely inferable from an import library. Supported by the annotation parser where the header states it. _Win32_SetLastError_ Must be explicit.
SupportedOSPlatform The RDL/winmd vocabulary exists, but ordinary SDK headers do not provide the version. Current values originated in external policy data unless already patched into a header. Choose a fixed macro such as _Windows_SupportedOS_10240_. Migrate supportedOS.rsp into headers using a reviewed macro menu. Each macro expands to a canonical version string, so individual declarations cannot mistype it.
Documentation No equivalent attribute exists in the current windows-rs metadata seed or header scraper. Scrape and cross-reference the Windows documentation sites by default. Retain _Win32_Documentation_("https://...") only as an override for missing or ambiguous matches. Revisit and automate the pipeline used to produce Microsoft.Windows.SDK.Win32Docs; the latest published package, 0.1.42-alpha, is more than three years old and the prior process appears to have required manual work.
SupportedArchitecture Inferred by comparing x86, x64, and ARM64 scrapes. An explicit architecture annotation remains useful for declarations hidden by preprocessing or exceptional policy. Prefer multi-architecture inference; retain an override.
Const The scraper writes native pointer constness into RDL as *const, but the RDL-to-winmd path currently loses the corresponding ConstAttribute. Use native C/C++ const. Fix the RDL-to-winmd loss once rather than adding a compensating header annotation. Fix the RDL compiler once rather than treating each affected API as a separate header gap.
ComOutPtr Recovered from _COM_Outptr_/[iid_is], or heuristically from an HRESULT method containing a conventionally named IID selector and a single-object void** output. Use standard SAL where it is already present: _COM_Outptr_, _COM_Outptr_opt_, or the corresponding _result_maybenull_ variant. No new annotation or broad header cleanup is needed. Preserve IID/PPV shape inference for existing declarations that use generic _Outptr_.
SAL semantic implied defaults Mutable pointers currently tend to surface as output-only. This does not match SAL's semantic implied defaults. No header annotation should be added merely to restate an implied default. Apply the semantic implied defaults: an unannotated pointer is In|Out with element count 1; an unannotated scalar is In.
Proposed rule: inferred values are allowed to establish the default, but the emitted winmd must still contain the corresponding semantic record, and an explicit header annotation must be able to override or supply every value that cannot be derived reliably.
Documentation TODO: investigate the former Microsoft.Windows.SDK.Win32Docs generation and cross-reference process, identify the authoritative windows-docs repositories and stable symbol keys, then define an automated refresh and publishing path. Do not shift thousands of documentation URLs into SDK headers unless a scraped match needs correction.

}

    UIntPtr Value;

[DllImport("ESENT.dll")]
int JetTerm(
    [In] JET_INSTANCE instance);

Proposed change

// No header annotation.

// Merge the conditional SDK typedef into one architecture-neutral
// metadata type:
struct JET_API_PTR {
    UIntPtr Value;
}

// Preserve the native typedef identity with a direct int underlying type:
struct JET_ERR {
    int Value;
}

JET_ERR JetTerm(JET_INSTANCE instance);
Architecture policy discussion: UIntPtr is the arch-neutral metadata representation of the SDK's conditional 32/64-bit typedef. Emitting only the 64-bit definition with architecture restrictions leaves the canonical winmd incomplete for x86. The multi-architecture merge should recognize this pattern and produce one pointer-sized type.
JET_ERR: retaining the native typedef is useful and requires no ProjectAs annotation. Collapse the redundant JET_ERR -> JET_INT32 -> int chain so JET_ERR is a distinct metadata struct with a direct int field, and APIs may return it directly.

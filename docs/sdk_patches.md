# SDK Header Patches

Patches modify SDK headers during ingestion to add metadata annotations (conditional enums, SAL attributes, etc.) until those changes ship in the official SDK.

## How It Works

Patches are unified diffs in `generation/WinSDK/patches/`, organized by phase:

```
patches/
  pre-midl/     ← Applied after SDK copy, before MIDL recompilation
  post-midl/    ← Applied after MIDL recompilation and header restores
```

**Pre-MIDL** patches target `.idl` files (or headers included during MIDL compilation). Changes flow through `ConvertMidlAttributesToSalAnnotations.ps1` → MIDL → generated `.h`.

**Post-MIDL** patches target `.h` files directly. Use this for headers not generated by MIDL (e.g., `Uxtheme.h`).

Both phases run automatically during `UpdateSDK.ps1` /
`RecompileIdlFilesForScraping.ps1`. The checked-in
`RecompiledIdlHeaders` SDK mirror is never modified: headers are copied to
`generation/WinSDK/obj/RecompiledIdlHeaders`, patched there, and the metadata
pipeline consumes that generated tree. If a patch fails to apply, the script
errors out; this signals the SDK changed and the patch needs regeneration.

## Naming Convention

```
<filename>.win32metadata.patch
```

Prefer one cumulative patch per source header. This keeps every staged metadata change
for a header reviewable in one diff and removes ordering dependencies between patches
that modify the same file.

```
patches/post-midl/
  errhandlingapi.h.win32metadata.patch
  prsht.h.win32metadata.patch
```

Use exactly one cumulative patch per source header unless a single diff is genuinely
too large to review. Any split must use non-overlapping, deterministically named
regions and be documented in the header and partition reports. Patches are applied in
sorted filename order within each phase.

## Creating a Patch

1. Run `RecompileIdlFilesForScraping.ps1` to generate the patched object tree.
2. Edit the target file under
   `generation/WinSDK/obj/RecompiledIdlHeaders/`.
3. Generate a cumulative patch with paths rooted at the checked-in
   `generation/WinSDK/RecompiledIdlHeaders` mirror.
4. Commit only the patch file. Never commit generated object-tree changes or
   modify the checked-in SDK mirror.

For IDL files, use `pre-midl/`:
```powershell
git diff -- "generation/WinSDK/RecompiledIdlHeaders/um/myfile.idl" `
  > "generation/WinSDK/patches/pre-midl/myfile.idl.my-reason.patch"
```

## Updating a Patch After an SDK Update

When `UpdateSDK.ps1` is run with a new SDK version:
1. The checked-in SDK mirror is refreshed.
2. A generated copy is created under `generation/WinSDK/obj`.
3. Patches are re-applied automatically to the generated copy.
4. **If a patch fails**: the SDK incorporated the fix (or changed the surrounding code). Regenerate or remove the patch.

To regenerate a failing patch against the new SDK:
1. Comment out the failing patch temporarily (or move it aside).
2. Re-run `RecompileIdlFilesForScraping.ps1` to get the new pristine baseline.
3. Make the edit, generate the new patch, commit.

## Removing a Patch

When the official SDK ships a fix, delete the `.patch` file and re-run `UpdateSDK.ps1`. The header will now contain the fix natively.

## Examples

**Header patch** (`post-midl/Uxtheme.h.win32metadata.patch`): Would contain all staged
metadata changes for `Uxtheme.h`, such as conditional enums, supported-OS annotations,
and signature typing.

**IDL patch** (`pre-midl/myfile.idl.my-reason.patch`): Would add a `cpp_quote` block to an IDL file. MIDL compiles it and the change appears in the generated `.h`.
